## TICKET G1 — Cascaron movil (Antigravity)

**Objetivo:** que ALFA OS se instale como app en el celular y tenga navegacion usable con el pulgar. Sin backend nuevo.

**Alcance:**
1. **PWA:** `app/manifest.ts` (o `public/manifest.json`), service worker (evaluar `@ducanh2912/next-pwa` o SW manual — Next 16, App Router), iconos (192/512/maskable) y splash. Instalable en iOS/Android, pantalla completa, sin barra de URL.
2. **`<MobileShell>`** (nuevo, `components/mobile/`): barra de pestañas inferior fija — Inicio / Proyectos / Vigía / Buscar / + Nuevo. Se activa por breakpoint (`< md`) o user-agent. En escritorio no cambia nada.
3. **3 pantallas mobile-first** (tarjetas, 1 columna, toques ≥ 44px, cero tablas con scroll lateral):
   - Brief/Bandeja del Vigía (`/vigia`) — reusar `getVigiaFindings`/`getVigiaOverview`, solo nueva presentacion.
   - Proyecto de un vistazo (`/projects/[id]`) — estado de compras, entregas, mano de obra, pagos, en tarjetas apilables.
   - Lista de cotizaciones (`/quotes`) — tarjetas con cliente, total, estado, fecha.

**Contrato:** no se toca ningun endpoint, server action, tabla ni RLS. Solo se agregan componentes y layout. Las pantallas de escritorio existentes no cambian de comportamiento.

**Definicion de listo:**
- Se instala en un iPhone y un Android y abre a pantalla completa con icono propio.
- Las 3 pantallas se usan con una mano sin zoom ni scroll horizontal.
- `npx tsc --noEmit` y `npm run build` en verde.
- Respeta ALFA Design System v1 (negro/blanco/vino, mucho espacio, sin cajas ni bordes de mas).
- Doc corta en `ia-cowork/ideas/` con capturas.

**No tocar:** lógica de negocio, el editor de cotizaciones de escritorio, permisos, portal cliente.

## TICKET G2 — Motor de borrador de cotizacion en servidor (Codex)

**Objetivo:** extraer el calculo de una cotizacion desde el componente cliente `app/(admin)/quotes/new/page.tsx` a un modulo de servidor reutilizable, con pruebas que garanticen que los totales cuadran exacto.

**Entregable:** `lib/quotes/draftBuilder.ts` con:

```ts
export type DraftQuoteInput = {
  client_id: number;
  items: Array<{ product_id: number; qty: number; margin_percent?: number }>;
  labor?: Array<{ labor_activity_id: number; qty: number }>;
  indirect_cost_percent?: number;   // default: el de settings/pricing
  notes?: string;
};

export type DraftQuoteResult = { quote_id: number; version: number; grand_total_mxn: number; warnings: string[] };

export async function buildDraftQuote(
  supabase: SupabaseClient,
  input: DraftQuoteInput,
): Promise<DraftQuoteResult>;
```

**Comportamiento:**
- Resuelve costo y datos de cada producto desde `products` (cost_price, cost_currency). Si un producto no tiene costo → `warnings` (no explota).
- Aplica margen (el de `input`, o el default del producto/categoria segun la logica actual de `quotes/new`), costo indirecto `%`, linea MISC por seccion, tipo de cambio (usar el mismo source que hoy: `exchange-rate` / `lib`), numeracion de cotizacion.
- Inserta `quotes` con `status = 'draft'` + `quote_items` con TODOS los campos derivados que hoy calcula el cliente (equipment_total, labor_total, line_total, subtotal_*, etc.).
- Idempotencia razonable: si se llama dos veces con el mismo input no crea duplicados silenciosos (devolver el draft existente o crear version — decidir con Claude).

**Pruebas golden (obligatorio):** `lib/quotes/__tests__/draftBuilder.golden.test.ts` — tomar 5+ cotizaciones reales existentes de la base, reconstruir su input, correr `buildDraftQuote` y **exigir que `grand_total_mxn` y los subtotales por linea coincidan al centavo** con la cotizacion original. Si no cuadran, el ticket no esta listo.

**Definicion de listo:**
- El modulo replica el calculo del cliente exacto (pruebas golden en verde).
- `npx tsc --noEmit`, `npm run build`, y las pruebas en verde.
- No cambia el componente `quotes/new` todavia (eso es un paso posterior: apuntarlo al modulo nuevo). Solo se agrega el modulo + pruebas.
- Doc en `ia-cowork/ideas/` con: que formulas se replicaron, que quedo fuera, y las cotizaciones usadas como golden.

**No tocar:** RLS, auth, el flujo de aprobacion de cotizaciones, facturacion, el editor de escritorio. Cualquier ambiguedad en la matematica → preguntar a Claude, no adivinar.
